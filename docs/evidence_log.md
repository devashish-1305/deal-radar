Generated by `scripts/collect_evidence.py` from `data/cases/evidence_queries.json`, `data/cases/evidence_overrides.json` and `data/cases/evidence_exceptions.json`. Do not edit by hand.

## Protocol
- **Searches used grouped OR-queries (one query per template per company), not exhaustive keyword-level searches. Same five templates for every company; no buyer names or deal terms.**
- Search tool: Claude Code WebSearch (standard mode); results recorded in the order returned; searched on 2026-10-27. No new searches after that.
- Templates (identical for every company):
  - T1: `"<name>" acquisition OR acquires OR sale OR sold`
  - T2: `"<name>" advisers OR adviser OR "strategic review" OR "exploring options"`
  - T3: `"<name>" CFO OR "chief financial officer" OR chair OR appoints`
  - T4: `"<name>" investment OR funding OR backed OR "private equity"`
  - T5: `"<name>" "invests in" OR "majority stake" OR "management buyout" OR "Series A" OR "Series B" OR "Series C"`
- **Pass 1** selection: In result order, open results whose title or URL contains one of the company's aliases (token match, case-insensitive), up to the per-template limit. Skip disallowed sites and URLs already opened for that company. No judgement of headlines. Per-template limit L = 3.
- **Pass 2** selection (Step 5.1, same 60 result lists, same rule for all 12 companies): In result order, open results whose title or URL names the company (aliases, token match, case-insensitive). The WebSearch tool returned only a title and URL per result, with no per-result snippet, so no snippets were logged and none could be used; no new searches were run to obtain them. URLs opened in pass 1 are skipped and count towards the limit. Per-template limit L = 6 (cumulative with pass 1). Aggregator profile sites skipped by domain: cbinsights.com, pitchbook.com, glassdoor.com, glassdoor.at, glassdoor.be, owler.com, crunchbase.com, dealroom.co, tracxn.com.
- Per-company cap = 10 kept items (pass 1 first; pass 2 fills remaining room; press releases first, then template order, then rank). Logged exceptions sit outside the cap and are listed explicitly.
- Source type: press_release if the domain is the company's own site, a PR wire or an investor (PE/VC) site listed above; otherwise news.
- Window: publication date in [anchor − 24 months, anchor), using the pair's anchor for both companies. `late` = [anchor − 3 months, anchor). Anything on/after the anchor is discarded.
- Publication dates: only schema.org `datePublished` or `article:published_time` from the fetched page (never modified/updated dates, `<time>` elements, search snippets or URL patterns). Conflicting or missing → None (kept, unusable). A manual date is used only from a visible dateline/byline quoted below.
- Leakage guard: a page whose metadata says it was modified on/after the anchor (`dateModified`, `article:modified_time`, `og:updated_time`) is discarded as `modified_after_anchor`, because its current text may post-date the anchor (CLAUDE.md: content published later never counts). Modified dates are never used as publication dates.
  - **Documented leakage example (LDC / HSL Compliance):** `ldc.co.uk/portfolio/hsl-compliance-investment-in-expansion/` states datePublished 2025-01-08 (before the 2025-02-04 anchor) but dateModified 2025-11-18, and its fetched text already reads "Exit type: Private equity sale · Exit date: January 2025". Without the guard it would have been kept as a pre-anchor page while carrying the outcome. It stays excluded, as do the other three pages the guard removed.
- **Content-leak check (Step 6a):** a page whose stored text names the pair's buyer (`data/cases/leak_check.json`, used only for this check, never in queries) or a target-outcome phrase (e.g. "<target> acquired by", "acquisition of <target>") is discarded as `content_leak`. Once a page carries post-anchor content we cannot know what else changed, so it is excluded, not sanitised. Stored raw text is not modified.
  - **Documented example (Oxford Ionics):** `thequantuminsider.com` article published 2023-09-01 (NSSIF £2m) whose fetched page carries the tag "Oxford Ionics [Acquired by IonQ]" and a related-article link "IonQ Completes Acquisition of Oxford Ionics" (Sept 2025).
- Ownership history: PE-backed → the current sponsor's investment announcement. VC-backed → the last priced round before the anchor, tagged only if the opened page documents it. **For VC-backed companies this is a funding-age proxy, not a holding-period start**; Step 7 decides whether to use it (exploratory only, not in PRD §8).
- Fetching: `requests` with robots.txt respected, 1 s per-domain delay. Blocked, paywalled, non-HTML or thin pages (< 400 chars of text) are logged and skipped, never worked around.
- **Missing evidence is never treated as absence of a signal.** A gap below means "not found by protocol".
